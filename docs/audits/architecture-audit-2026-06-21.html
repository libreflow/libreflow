🚀 Séquence de démarrage

Ordre d'exécution (app.js boot())

1. openDB()
Connexion IndexedDB 'lp4' v5 — bloquant, tout attend.
2. Promise.all([dall('playlists'), dall('playlog'), dall('tracks')])
3 lectures IDB en parallèle. dall('tracks') = lecture entière — potentiellement 10–30 MB à 50k tracks. Timeout 30s.
3. rebuildTrackIdxMap()
Map<id→idx> O(n) synchrone — ~2ms à 50k tracks. Invariant critique §2.
4. radioRefillQueue() avant updateBar()
Ordre load-bearing. Inversion = bug silencieux. Invariant §2.
5. renderLib() + virtBuildRows()
Premier rendu. Descripteurs lignes + prefix-sum Int32Array.
6. loadTagsBg() — background
Tags ID3 manquants, concurrence 8 (CFG.TAG_LOAD_CONCURRENCY). Non bloquant.

✅ Points forts de l'architecture

Architecture solide

✓ store.js — réactif minimal (181L), zéro dep, re-entrancy guard, setBatch atomique
✓ bus.js — EventBus typé, EVENTS constants, unsubscribe propre
✓ ipc.js — timeout systématique, waitTauriReady(), invokeRetry + backoff
✓ virt.js — Int32Array prefix-sum, binary search O(log n), ±8 buffer, 0 alloc rAF
✓ state.js — mutations atomiques tracks[] avec rebuild garanti (ARCH-3)
✓ cfg.js — toutes les magic numbers centralisées, frozen Object
✓ search.js — NLC cache par génération (O(1) invalidation), trigrams lazy
✓ artLoader.js — LRU cache 200 blob:URL, IDB sans cover art base64

Invariants bien gardés

✓ Offline garanti — zéro fetch/XHR/WebSocket, fonts @fontsource
✓ IDB writes débouncés (250ms tracks, 800ms cfg, 3s playlog)
✓ audio.volume jamais assigné — DOM #vol slider = source de vérité
✓ setTargetAtTime() partout — pas de zipper noise garanti
✓ Pas d'innerHTML avec contenu non sûr — thtml() échappe systématiquement
✓ Tags lofty sanitizés (_sanitizeTagStr, maxLen=500)
✓ WCAG 2.1/2.2 AA — focus ring dual-tone, aria-current, role=dialog
✓ removeTracksBatch() — tri défensif + rebuild unique

📋 Résumé exécutif

LibreFlow est un player desktop offline bien architecté avec des invariants critiques solidement gardés. La base technique — store.js, bus.js, ipc.js, virt.js — est propre et extensible.

Goulot principal — structural : app.js est un god module (50+ imports) qui crée un couplage fort. Le refactoring ARCH-1 est sur la bonne voie mais incomplet. 6 fichiers JS dépassent le cap de 800L, dont i18n.js à presque 2×.

Goulots de performance : concentrés sur le boot (dall() full scan) et les premières mutations après import (rebuildTrackIdxMap O(n), virtBuildRows O(n)). À 50k tracks, ces opérations restent dans des bornes acceptables mais le lazy-load au boot serait l'amélioration la plus impactante.

Action n°1 : splitter i18n.js, renderer.js et playlists.js pour revenir sous 800L. Ratio impact/risque maximal — aucun comportement modifié.
