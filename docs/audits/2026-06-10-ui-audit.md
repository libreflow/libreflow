**Date** : 2026-06-10
**Auditeur** : Lead Product Designer & Design Engineer (Claude, 5 agents d'inventaire parallèles)
**Périmètre** : UI/design uniquement — tokens, hiérarchie, patterns streaming, états, motion, a11y, responsive.

## Verdict global : 7.9/10 — fondation excellente, finitions à discipliner

libreflow n'est **pas** une app à refondre. Le design system est mature (source unique `design-system.css`,
1064 lignes, test-enforced), la signature visuelle existe déjà (Electric Indigo `#8B6BFF` + Syne/DM Sans +
ambient k-means), et la couverture des patterns streaming est de l'ordre de 85-90 % de Spotify/Apple Music
2025-2026. Le travail d'élévation est un travail de **discipline**, pas de réinvention : résorber les valeurs
en dur résiduelles, fermer les trous reduced-motion sur les canvas, corriger 3 incohérences sémantiques,
et garantir le contraste sur artwork dynamique.

## Findings priorisés

### CRITIQUE (bloquant niveau 2026)

**CR-1 · Les boucles canvas ignorent `prefers-reduced-motion`** — effort S/M
`motion.js` (façade GSAP) et le CSS couvrent 100 % de leur périmètre, mais les animations *bitmap*
y échappent : `nowplaying.js` (particules ambient, rAF 60fps), `cinema-bg.js:101` (breathing ambient),
`cinema.js:57` (LERP couleur `_LERP_K=0.06`), `viz.js` (rAF sans guard), `oscPremium.js`.
Un utilisateur ayant demandé la réduction de mouvement reçoit quand même des particules animées plein écran.
**Fix** : guard `prefersReducedMotion()` (importé de `motion.js`) à l'entrée des boucles rAF décoratives ;
rendu statique (1 frame) pour les fonds ambient. Le visualiseur `viz.js` est opt-in utilisateur
(motion « essentielle » au sens WCAG 2.3.3) → guard non obligatoire mais frame-rate réduit recommandé.

**CR-2 · Texte sur artwork sans garantie de contraste** — effort S
*(Constat affiné à l'implémentation : `#vnp` possède déjà un scrim adaptatif — `::after` rgba(0,0,0,.38)
+ bascule `art-light` par luminance — et `.cinema-title/artist` ont leur text-shadow.)*
Trous réels : `.vnp-title/.vnp-artist/.vnp-album` (style.css:6531+) sans text-shadow sur canvas ambient
(luminances intermédiaires), et `.cinema-album` (alpha .42, aucun shadow, style.css:5069).
**Fix CSS statique** : `text-shadow: var(--tshadow-title)` garanti (annulé sous `art-light`), alpha
`.cinema-album` .42→.50 + shadow.

### MAJEUR

**MA-1 · Sémantique des boutons de modale incohérente** — effort S
« Vider la bibliothèque » (action la plus destructrice de l'app) utilise `.mbtn.confirm` (accent positif,
index.html:375) alors que le confirm générique utilise correctement `.mbtn.danger` (index.html:386).
3 styles co-existent pour le même rôle (`confirm`/`danger`/sans variante : organize-confirm, cd-extract).
**Fix** : règle unique — destructif = `.danger`, validation = `.confirm`, neutre = sans variante.

**MA-2 · Cibles tactiles figées à 24px en mobile** — effort S
`--target-min: 24px` (design-system.css:600) est consommé par 8 règles (boutons icône inline) mais ne suit
pas `--tap-target` (48px en `data-platform="mobile"`, 36px PC).
**Fix** : redéfinir `--target-min` à 44px dans le bloc `data-platform="mobile"` (SC 2.5.8 AAA tactile).

**MA-3 · ~30 z-index + ~20 rgba() bordures + ~20 font-size en dur dans style.css** — effort M
Z-index littéraux 0/1/2/3/5/10 (ex. style.css:1599-1843, 4777, 4851) au lieu de `--z-base/raised` ;
`rgba(255,255,255,.15)` etc. au lieu de `--border-*` (ex. :145) ; font-size 9-22px au lieu de `--text-*`.
Risque réel : refactor de stacking context et dérive de palette en light mode.
**Fix** : migration mécanique vers tokens, par lots, test `token-source` + `theme-palette` en garde-fou.

**MA-4 · Deux systèmes de modales** — effort L (dette à phaser, pas un quick fix)
`modal.js` (trapFocus legacy, 9 modales) vs `<lf-modal>` (Lit, 1 modale). Double maintenance du focus trap.
La migration Lit Phase 1+ (CLAUDE.md §18) est déjà la trajectoire prévue — à planifier par spec dédiée,
pas dans cette passe.

**MA-5 · Affordance de retour en drill faible** — effort M
`#breadcrumb` et `#drill-header` se recouvrent partiellement ; pas de bouton retour explicite dans la vue
drill ; `.bc-link` se distingue du texte uniquement par la couleur (SC 1.4.1 limite, style.css:1872).
**Fix court terme** : underline au repos sur `.bc-link`. Long terme : unifier breadcrumb/drill-header.

**MA-6 · Pas de skeleton sur les grilles** — effort S/M
Les rows ont un shimmer soigné (style.css:1349-1384) ; les grilles albums/artistes apparaissent d'un bloc
après `_deferGridRender` (views.js:91-99).
**Fix** : skeleton cards réutilisant `--anim-shim` + dimensions réservées (déjà le cas via aspect-ratio).

## Décision Phase 3 (résumé)

Le design system cible **existe déjà** — il sera documenté, pas réinventé (voir
`docs/superpowers/specs/2026-06-10-design-system-target.md`). La signature visuelle retenue est celle
déjà en place : **système couleur adaptatif ambient (k-means 3 zones) + Electric Indigo constant + Syne**.
Une seule audace, déjà exécutée — on la consolide (CR-2, reduced-motion CR-1) au lieu d'en ajouter une.

## Plan Phase 4 (ordre d'exécution)

1. CR-1 — guards reduced-motion canvas (cinema.js, cinema-bg.js, nowplaying.js, oscPremium.js)
2. CR-2 — scrim garanti texte-sur-artwork (style.css)
3. MA-1 — sémantique `.mbtn.danger` (index.html ⚠ fichier déjà modifié, non commité)
4. MA-2 — `--target-min` adaptatif mobile (design-system.css)
5. MA-3 — migration tokens z-index / bordures / font-size (style.css, par lots)
6. MA-5 court + MI-1/MI-2/MI-3 — underline bc-link, token tabular-nums, transition zoom
7. MA-6 — skeleton grilles

Hors scope de cette passe (specs dédiées) : MA-4 (migration lf-modal), MI-4 (continuité spatiale), MI-6.
